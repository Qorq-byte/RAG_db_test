# 切换知识集合保持当前会话

## 问题与修复

用户明确要求：切换知识集合只改变提问所用的资料范围，只有主动选择会话或点击“新会话”才切换会话。此前界面在集合变化时清空会话ID和消息，服务端也拒绝会话使用其他集合继续提问。

源码 `5d40237` 修复两处限制：

- 集合切换保留当前会话ID、消息、引用和未发送草稿；当前会话不在新集合的最近记录中时，仍保留在下拉框并保持选中。
- 每次提问以当前选中的集合检索，成功回答追加至同一个会话。每条历史回答保留原有引用快照，不改写历史来源。
- 对话历史继续用于理解上下文；模型提示明确历史回答不是本轮证据，引用编号以本轮证据为准。新集合没有检索依据时，直接保存拒答，不调用模型。
- 失败或停止后的重试使用当前显示的集合，避免按钮因旧集合上下文失效而无响应。已主动切换离开的会话不允许旧按钮触发重试。
- 只有主动选择/新建会话才替换显示；主动删除当前会话仍按既有规则进入新会话。生成中的切换保护及迟到事件过滤继续有效。

## 存储边界

不迁移数据库或移动会话档案。会话仍按首次创建时的集合归档，可回该集合查找完整历史；集合切换不创建副本。历史管理与CLI会话查看/删除仍按归档集合筛选，删除归档集合仍会级联删除其会话。每次问答使用的检索集合与这个归档位置是不同概念。

本次没有新增全局会话列表，也没有修改模型配置、资料索引或现有用户记录。

## 验证证据

- 修复前两项复现测试均失败：界面切换后会话ID变为None，服务端对同一会话的跨集合提问抛出NotFoundError。
- 相关服务10项、桌面及流式54项通过。覆盖同一会话两轮使用不同集合、各轮引用独立、重新打开后完整恢复、无依据拒答、失败/取消不污染原记录、切换后重试、显式选择会话、新建会话及既有会话删除。
- 新增显式选择测试曾因合成模型仅实现流式接口、测试调用却使用默认非流式而失败；补充 `stream=True` 后复验54项全部通过（34.21秒）。此修正仅调整测试调用，与产品逻辑无关。
- 最终全项目分组 **452项通过，0失败、0错误、0跳过**：核心316项（266.05秒）、桌面联合54项、其余Qt82项。XML用例集合与全量收集清单逐项比对，无遗漏或重复。各组计数、耗时与报告SHA256见[回归汇总](2026-09-27-chat-session-preservation-regression.json)。一条警告来自预期的重复ZIP拒绝测试。原始报告位于本地忽略目录 `.data/chat-session-preserve-*.xml`。
- Windows原生隐藏窗口复核：载入原集合的已保存会话，再切换资料集合，选中会话、两条历史消息及草稿均保留。使用临时合成数据，截图为 `.data/chat-session-preserved.png`。

所有会话均来自临时合成数据库；未使用真实用户会话或云端模型。源码分步推送，安装包继续保持不变，须用户明确同意后更新。

# 检索增强问答与会话记忆实施计划

本计划落实已批准的 `2026-09-23-rag-chat-memory-design.md`。每一步均在当前主线完成定向测试、单独提交并推送；最后执行全量回归。

## 步骤 1：领域模型、SQLite 迁移与会话仓储

- 定义会话、消息、引用快照及其不可变角色枚举；扩展领域端口。
- 将 SQLite schema 从 v1 迁移至最新版本，支持新库初始化和既有库的无损升级。
- 实现会话仓储的创建、按集合读取、消息/引用原子写入、列表与删除，并验证外键级联。
- 测试：模型约束、v1 升级、顺序与引用快照、集合隔离和级联删除。

## 步骤 2：聊天配置与模型基础设施

- 增加严格 `chat` 配置和密钥脱敏加载，补充示例配置与诊断。
- 定义 `ChatModel`、标准聊天消息和生成结果；实现工厂。
- 以 mock HTTP transport 实现并测试 OpenAI 兼容和 Ollama 适配器的成功及失败转换。
- 测试：配置验证、密钥不从 TOML 读取、两种 provider 的请求/响应/错误行为。

## 步骤 3：受证据约束的问答应用服务

- 实现提示词与证据格式化、检索结果去重、稳定编号和历史字符预算截断。
- 实现会话创建/续接、严格集合归属校验、空检索固定拒答与成功轮次原子持久化。
- 测试：证据限制、空检索不调用模型、历史截断、引用持久化、模型失败不留下半轮消息。

## 步骤 4：CLI、可用性与文档

- 增加 `ragdb chat ask` 和会话的 list/show/delete 命令，复用现有集合查找和破坏性操作确认。
- 输出会话 ID、回答与可定位的去重来源映射；接入操作日志。
- 更新 README、配置示例和 doctor；端到端覆盖新建、续接、隔离、显示、删除与配置错误。

## 步骤 5：验收

- 运行 `uv run pytest` 全量回归、`ragdb chat --help` 和相关 CLI 帮助检查。
- 复核工作树、README 命令示例与不含密钥的日志/配置契约。
- 提交并推送验收记录。

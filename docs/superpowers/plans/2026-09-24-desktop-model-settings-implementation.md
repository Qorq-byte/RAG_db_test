# 桌面端模型设置实施计划

## 目标

按已批准的 [模型设置设计](../specs/2026-09-24-desktop-model-settings-design.md) 实现桌面模型设置，让用户可配置并测试问答/生成模型与嵌入模型；切换嵌入模型时，对所有集合安全地重建向量并在成功后启用。

## GitHub 交付约定

- 阶段 1–3 工作分支：`codex/desktop-model-settings`（已合并 main）；阶段 4：`codex/desktop-model-settings-ui`。
- 每个步骤独立验证、形成单独提交并推送到同名 GitHub 分支；不提交用户已有的测试修改或“前端设计”草稿。
- 验证失败时先修复并重跑受影响检查，再提交该阶段。

## 阶段

当前状态（2026-09-24）：阶段 1–4 已完成，阶段 5 待执行。阶段 4 提交 `a8240ae` 已推送功能分支，尚未合并主线；完整交付记录见 [progress.md](../../../progress.md)。

### 1. 模型设置服务与凭据

- 新增模型设置服务：读取/保存非敏感配置、识别环境变量与 `.env` 覆盖、运行 Chat 与 embedding 连接测试。
- 增加 Windows 系统凭据存储适配器，API Key 不进入 TOML、SQLite 运行日志或界面回显。
- 给 Ollama 适配器增加已安装模型列表查询；连接测试使用固定最小请求，不影响知识库数据。
- 配置保存采用保留现有 TOML 注释和其他段落的写入方式；凭据接口不可用时失败关闭。
- 验证：服务单元测试覆盖配置来源、密钥读写/清除/不回显、Ollama 列表、两类 provider 的成功与失败；相关既有配置和适配器测试通过。
- 提交：`feat: add model settings service`；推送。

### 2. 活动嵌入索引配置与向量命名空间

- 扩展 SQLite schema，持久化活动嵌入配置指纹、非敏感配置和全局重建状态；旧数据库初始化为当前默认 Chroma 命名空间。
- 扩展 Chroma 适配器，按知识集合 UUID 与嵌入配置指纹使用独立命名空间，避免不同维度向量冲突。
- 更新 `ApplicationRuntime`、检索、导入、删除集合/资料等路径，使其使用活动命名空间；兼容现有默认向量集合。
- SQLite 活动指纹是运行时权威状态；TOML 配置与之不同步时启动以活动配置恢复，避免索引/模型错配。
- 验证：旧 schema 无损迁移、配置指纹稳定性、不同维度命名空间隔离、活动命名空间路由及原功能兼容测试。
- 提交：`feat: version embedding vector namespaces`；推送。

### 3. 全集合分阶段嵌入重建

- 新增应用服务，从 SQLite 读取每份来源当前有效代次的切片文本，适用于本地文件、网页、GitHub 和手动文本；保留文本分块和 FTS 索引。
- 在新暂存命名空间批量嵌入并写入，提供集合/资料进度与取消支持；SQLite 闸门阻止 CLI 和桌面在重建期间导入新资料。
- 全部验证成功后，以 SQLite 事务一次性发布活动指纹与来源嵌入元数据；保留旧命名空间。失败或取消时旧索引继续工作，并清理未发布暂存数据。
- 验证：跨多个集合和来源类型重建；测试写入/嵌入/发布故障、取消、重启恢复与导入闸门，证明旧配置下检索仍可用；成功后新配置检索可用。

#### 5.3 真实模型与凭据联调

前置条件：可访问的 Ollama 与已安装模型、本地嵌入模型或获准下载的环境，以及用户指定的云端服务、模型和测试凭据。凭据只通过设置页或本地环境配置提供，不写入文档、日志或 Git。

| 验收项 | 操作 | 通过标准 |
| --- | --- | --- |
| 本地问答 | 刷新 Ollama 列表、测试、保存、重启、问答 | 返回真实响应，重启保留配置，后续请求使用所选模型 |
| 云端问答 | 确认固定文本测试，保存密钥后重启 | 服务正常响应；真实系统凭据可恢复；页面和配置文件不泄露密钥 |
| 本地嵌入 | 在隔离测试集合切换本地模型并检索 | 全部测试切片重建成功，活动模型一致，新索引可检索 |
| 云端嵌入 | 明确确认发送合成测试资料后重建 | 服务正常返回向量，成功后切换；不发送用户真实知识库资料 |
| 失败与取消 | 使用受控失败或取消测试 | 未发布候选模型，旧索引仍可检索；清理后可以重试 |
| 密钥隔离 | 测试不同服务地址与清除凭据 | 新地址不沿用旧服务密钥；清除作用于所选目标 |

- 本地/云端实际响应与自动化替身测试分开记录，不以替身测试冒充真实联调。

## 风险与处置

- 向量维度不可混用：新模型必须写到指纹隔离的 Chroma 命名空间，发布前不触碰旧命名空间。
- 配置文件和 SQLite 不能共同事务提交：运行时以 SQLite 活动指纹为准；启动时对 TOML 做一致性修复。
- 云端测试会发送固定测试文本，UI 在发送前告知可能计费；异常不得带出 API Key。
- keyring 后端在 Windows 上不可用时，不回退到明文文件；设置页明确报告无法安全保存凭据及修复方式。
- 用户工作区现有 `tests/integration/test_collection_cli.py` 改动和未跟踪 `前端设计/` 目录属于用户内容，不进入本分支提交。

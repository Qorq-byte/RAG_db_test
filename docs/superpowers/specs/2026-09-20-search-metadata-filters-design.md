# 搜索元数据筛选设计

## 背景与目标

当前 `ragdb search` 已支持按资料类型和资料 ID 筛选，且会向 SQLite FTS 与 ChromaDB 向量检索传递同一份筛选映射。本设计补齐标签、课程、作者和日期筛选，且要求多标签为交集：返回资料必须包含每个请求标签。

目标是让受控元数据在导入、持久化、两条召回路径和搜索结果之间保持一致。范围不包括为旧资料猜测或迁移元数据，也不包括任意 JSON 查询语言。

## 已考虑方案

1. **规范化元数据与专用索引字段（采用）**：导入时验证四类字段；SQLite 直接查询规范化元数据，ChromaDB 使用标量和每标签布尔字段。它能稳定实现标签交集。
2. **直接筛选 JSON/字符串数组**：SQLite 可行，但 ChromaDB 的字符串数组筛选兼容性不足，无法可靠地实现 AND。
3. **先召回再过滤**：代码改动少，但固定候选池可能被过滤为空，因而遗漏应返回的资料。

## 用户接口与数据契约

受控资料元数据：

| 字段 | 值 | 导入参数 | 搜索参数 |
| --- | --- | --- | --- |
| `tags` | 非空字符串列表 | 重复 `--tag` | 重复 `--tag`，全部匹配 |
| `course` | 非空字符串 | `--course` | `--course` |
| `author` | 非空字符串 | `--author` | `--author` |
| `date` | `YYYY-MM-DD` | `--date` | `--date-from`、`--date-to` |

单文件、目录和手动文本导入都接收这些参数；目录参数应用到该次导入的每一个资料。筛选条件与已有 `--source-type`、`--source-id` 以 AND 组合。

规范化规则：文本值去首尾空白并进行 Unicode NFC 规范化；英文标签、课程和作者以 Unicode 大小写折叠后比较；标签去重。日期由严格 ISO 日期解析器验证，并序列化回相同的零填充格式。搜索结果保留原先写入的、便于展示的元数据值。

## 架构与数据流

新增一个独立的元数据规范化/筛选模块，作为 CLI、导入服务和检索适配器的唯一字段定义来源。CLI 将选项转为受控元数据或筛选对象；导入服务把已规范化资料级元数据保存到 `Source.metadata`，并在分块后合并到每个 `Chunk.metadata`。重新导入同一路径时，以本次参数完整替换受控字段，避免旧标签残留。

SQLite 继续将完整元数据 JSON 持久化在 `chunks.metadata_json`。关键词检索使用 SQLite JSON 函数：对每一个请求标签分别验证 JSON 数组中存在该值；课程、作者做相等比较；日期用 `>=` / `<=` 比较。日期格式保证字典序与时间顺序一致。

ChromaDB 保留序列化后的完整元数据用于还原 `Chunk`。同时写入可查询的标量字段：规范化课程、作者和日期。每个标签写入一个内部布尔字段，名称由标签规范化值的 SHA-256 派生；查询为每个标签生成一个等于 `true` 的子句，并通过 `$and` 组合。这样避免对字符串数组筛选行为的依赖。内部索引字段不得出现在 CLI 输出或领域模型的用户元数据中。

`SearchService` 在获得查询嵌入前验证并规范化筛选条件，然后将该对象原样传给向量与关键词路径；因此 RRF 与可选重排序只处理已满足所有条件的候选。

## 失败处理与兼容性

- 空标签、无效日期、开始日期晚于结束日期、或无效受控字段，以中文的参数错误退出，不访问任一检索后端。
- 未筛选检索保持现有行为。
- 不自动回填历史资料的元数据。新导入及重新导入资料才会有相应索引字段。
- 对无法安全表示的后端筛选条件明确报错，不可悄然忽略条件或回退到召回后过滤。

## 测试与验收

- 单元测试覆盖规范化、日期边界和非法输入。
- CLI 测试覆盖受控元数据导入选项及搜索选项的传递。
- SQLite FTS 与 ChromaDB 各自覆盖：标签交集、课程、作者、日期以及与资料类型/ID 的组合。
- 集成测试证明元数据可从资料传播到切片和返回的 `SearchHit`，重导入会替换受控元数据。
- 回归测试证明无筛选时的结果和现有 `--source-type` / `--source-id` 行为不变。

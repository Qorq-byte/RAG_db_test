# 环境诊断与 README 设计

## 目标

以 `ragdb doctor` 替代占位命令，提供无需联网、无需下载模型且不修改知识库内容的分级环境诊断。同时补齐 README，使新用户能够安装、配置并使用已有的集合、导入、检索、抓取、监听与重建命令。

## 已选方案

诊断逻辑放在独立模块中，向 CLI 返回结构化检查结果：状态、检查名称、详情和修复建议。CLI 只负责按固定格式显示结果并根据汇总状态设置退出码。这使检查可单独测试，且不与业务运行时初始化耦合。

## 检查项与严重度

- Python 版本必须满足项目约束 `>=3.11,<3.12`，否则失败。
- 配置按既有 `--config`、`.env` 和环境变量优先级解析；无效配置为失败。配置文件缺失但可使用默认值时为警告。
- 数据目录以不留下文件的权限探测判断是否可用；不可创建或写入时为失败。
- SQLite 在内存数据库中创建 FTS5 虚拟表；不支持时为失败。
- ChromaDB 仅导入其 Python 包；无法导入时为失败。
- Git 仅定位并执行版本查询；不可用时为警告，因为仅仓库导入依赖它。
- 本地嵌入模式仅验证 `sentence_transformers` 可导入，不实例化或下载模型；缺失时为失败。
- 云端嵌入模式只验证模型名、Base URL 和 API Key 是否已配置，绝不向服务发送请求；缺项时为失败。

每项输出“通过 / 警告 / 失败”、详情和适用的修复建议。仅出现失败时命令返回非零；只有警告时返回 0。

## README

README 以中文说明安装要求、安装命令、从 `config.example.toml` 创建配置、环境变量中的云端密钥、主要 CLI 示例、`doctor` 状态含义和隐私边界。文档不承诺尚未实现的初始化命令，使用现有命令的真实行为。

## 验证与提交边界

1. 本设计文档。
2. 结构化诊断模块、CLI 接入和单元测试，覆盖成功、警告、失败、配置错误和退出码。
3. README 与文档回归检查。

每个边界作为独立提交推送至当前 `origin`。不会暂存工作区中已有的无关改动。

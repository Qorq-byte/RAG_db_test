# 第一阶段收尾设计

## 目标

完成首版个人 RAG 知识库的剩余验收能力：可预测的初始化、可查看的批处理记录与日志、可选的本机 OCR、索引配置漂移保护，以及网络导入的有限重试和更完整的环境诊断。第二阶段的问答、生成能力和桌面应用不在本次范围内。

## 交付边界

工作拆成四个可独立验证、提交和推送的步骤：

1. 实现 `ragdb init`、任务查询与操作日志查询，并为目录导入输出逐项进度。
2. 安装到 `D:\Dinstall` 的 Tesseract，并实现配置驱动的本机 OCR 重试、OCR 环境诊断和测试。
3. 记录资料的索引指纹，在解析器、分块器、嵌入模型或向量维度变化时拒绝静默混用索引并提示 `reindex`；为网页抓取增加有限重试。
4. 更新 README、配置示例和验收测试，完成全量回归。

## 初始化、任务与日志

`ragdb init` 显式创建配置所指的数据目录、SQLite 数据库、Chroma 数据目录与日志目录，但不创建集合。若已初始化则输出幂等提示。运行时日志写入数据目录中的轮转日志文件，并对云端密钥进行脱敏。

批量目录导入在每个文件完成后立即输出结果与累计进度，并保留现有最终汇总。新增 `ragdb task list --collection NAME` 和 `ragdb task show TASK_ID`，展示已有任务及其成功、更新、跳过和失败计数。操作日志记录集合创建/删除、资料导入/删除、重建和 OCR 重试；通过 `ragdb log list` 查询最新记录，可按集合筛选。

## OCR

OCR 使用系统安装的 `tesseract.exe`，目标安装目录为 `D:\Dinstall`。配置新增 `[ocr]`：`enabled` 默认为 `false`，`executable_path` 为可选路径，`languages` 默认 `chi_sim+eng`，并限制渲染 DPI。未启用时保持当前扫描 PDF 的 `OCR_REQUIRED` 行为。

启用后，PDF 解析器只针对文本稀少页面以 PyMuPDF 渲染 PNG，再以 `tesseract IMAGE stdout -l LANGUAGES` 调用本机程序，并把识别文本保存在对应页的位置中。缺少可执行文件、语言包或识别失败会给出安全、可操作的错误；不会联网、上传文档或把图像写入知识库。`doctor` 仅检查可执行文件、版本和语言包，不调用 OCR。

## 索引兼容性与网络导入

资料在成功索引时保存一个非敏感指纹：解析器名称/版本、分块配置、嵌入供应商、模型和向量维度。导入和检索发现当前配置与集合内就绪资料的指纹不一致时，拒绝操作并指引用户执行显式 `ragdb reindex --collection NAME`。重建完成后新指纹成为该集合的有效指纹。

网页抓取对临时 HTTP 失败和连接错误实行固定次数的指数退避重试；仍遵守已有 robots、同源、速率、超时、深度和页数限制。不可恢复的 4xx 与 robots 拒绝不会重试。`doctor` 静态验证抓取设置与 Git 可执行文件；不发起网络请求。

## 验证与安全

- 测试初始化幂等性、任务/日志展示、进度输出和敏感信息脱敏。
- 用伪造的 Tesseract 执行器和临时 PDF 测试 OCR 成功、未启用、缺失语言包和失败路径；实际安装后用 `doctor` 验证 Tesseract。
- 测试配置漂移会阻止检索和增量导入，且重建可恢复；测试网页临时错误重试上限。
- 每一步运行相应测试并独立提交、推送；最后运行完整测试套件。

## 非目标

本次不增加云端 OCR、后台守护进程、CI/Docker、LLM 问答、摘要生成或桌面 UI。

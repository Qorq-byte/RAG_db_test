# 桌面端实际体验与交互完善设计

## 目标

在不改变 RAG 业务语义、存储模型或 CLI 契约的前提下，完善 PySide6 工作台的导航效率、操作反馈和键盘可访问性。此次工作只扩展桌面展示层、窗口状态与界面控制边界。

## 范围与交付顺序

按风险从低到高分三阶段实施；每阶段独立测试、提交并推送，最后执行完整回归。

### 第一阶段：导航与窗口布局

- 侧栏支持 160–400px 的拖拽调宽；拖拽手柄可鼠标操作并具有工具提示和键盘焦点。
- 持久化侧栏宽度、折叠状态和详情栏开合状态；启动时恢复到合法值。
- 当窗口宽度低于 1100px 时，临时收起侧栏并隐藏详情栏；窗口恢复宽度后还原用户持久化的偏好，不把临时响应式状态写入设置。
- 主题的“减少动效”统一作用于侧栏宽度、悬停高亮和详情栏切换；开启时立即完成状态切换。

### 第二阶段：页面内操作反馈

- 对导入、检索、问答和学习内容生成统一呈现空闲、执行中、成功与失败状态。
- 提交操作后禁用对应入口，避免重复请求；后台任务结束后无条件恢复可操作状态。
- 成功反馈说明结果摘要，并仅刷新当前集合中受影响的数据区域；失败反馈保留可操作的错误信息，不使用阻断式弹窗承载普通后台失败。
- 以集合上下文代次作为后台结果的有效性令牌；切换集合后，旧任务不得覆盖当前页状态。

### 第三阶段：键盘与可访问性

- 所有导航、主要操作、详情栏关闭和弹窗确认均拥有可见焦点和可访问名称、描述或工具提示。
- `Ctrl+1` 至 `Ctrl+6` 跳转到六个工作台页面；`Ctrl+B` 折叠或展开侧栏；`Esc` 优先关闭详情栏，其次关闭当前模态窗口。
- Tab 顺序遵循视觉及任务顺序，不把隐藏的侧栏项目或详情栏控件留在焦点链中。
- 不以颜色作为唯一状态表达；状态徽标继续保留文本，焦点和禁用状态具备高对比度。

## 架构

- `ThemeManager` 继续是 UI 偏好的唯一持久化入口，新增窗口布局相关键及合法值归一化方法。
- `SidebarWidget` 只管理导航展示、悬停/宽度动画、用户拖拽和折叠信号；不持有业务服务或集合数据。
- `MainWindow` 协调持久化偏好与响应式临时状态，并集中注册窗口级快捷键和 Escape 行为。
- 复用并小幅扩展现有 `BackgroundTask` 和页面状态组件，以通用状态控制器封装“执行中禁用—结果校验—恢复入口”的生命周期；页面保留各自的业务调用。

## 错误处理与状态规则

- 布局设置缺失、格式不正确或超出范围时回退到默认值（侧栏 236px、详情栏打开、侧栏展开）。
- 任何后台任务完成、失败或过期后都必须清理任务引用并恢复触发控件；过期结果仅丢弃展示更新，不覆盖已持久化的业务结果。
- 键盘快捷键不拦截正在编辑多行文本时的常规输入；关闭模态对话框时遵守 Qt 原有接受/拒绝语义。

## 验收

- Qt 定向测试覆盖布局恢复、拖拽边界、窄窗临时状态、减少动效、快捷键、焦点链与 Escape 优先级。
- 覆盖一个后台操作的重复提交防护、成功/失败恢复和集合切换后过期结果丢弃；现有导入、检索、问答和学习产物页面保持可用。
- 执行 `uv run pytest` 完整回归，并在 Windows 桌面环境手工检查 1280×800 和 1024×640 两种窗口尺寸。

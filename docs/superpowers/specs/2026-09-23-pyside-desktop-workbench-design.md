# 第二阶段：PySide6 桌面工作台设计

## 目标与交付

为现有个人 RAG 知识库增加 Windows 原生桌面工作台，覆盖集合与资料、导入、检索、问答、学习产物、任务日志和环境诊断。首版通过 `uv run ragdb-gui` 启动，不构建 EXE，也不在界面中保存 API 密钥。

## 架构

桌面端使用 PySide6，直接调用现有应用服务，不解析 CLI 输出，也不启动本地 HTTP 服务。视图只处理展示和用户交互；桌面控制器将界面输入转换为领域调用；统一后台任务执行器通过 `QThreadPool` 执行导入、检索、模型调用、重建索引和诊断，并将结构化成功或失败信号送回主线程。

现有 CLI 中的对象装配逻辑应提取为可复用的运行时工厂，CLI 和 GUI 共享该工厂，避免形成两套配置、数据库和模型初始化路径。

## 主窗口与导航

主窗口采用左侧主导航、中央工作区和可折叠右侧详情栏：

- 概览：当前集合、资料数量、最近任务、会话和学习产物快捷入口。
- 集合与资料：集合 CRUD；文件、目录、文本、网页和公开 GitHub 仓库导入；资料列表和删除。
- 检索：查询与常用筛选、结果列表、来源位置和各阶段评分。
- 问答：新建/选择会话、消息流、可点击来源编号和历史会话管理。
- 学习产物：五种生成类型、主题、可选资料范围、历史产物查看和删除。
- 任务与诊断：导入任务、操作日志、配置和运行环境检查。

当前集合是全局上下文。切换集合后，所有页面刷新集合相关内容，并丢弃尚未呈现的旧集合只读任务结果。右侧详情栏统一显示资料、检索结果、问答引用、产物引用和错误详情。

## 交互与后台任务

所有可能阻塞的操作均在后台执行。每个任务携带页面和集合上下文；完成时控制器确认上下文仍有效后再更新界面。用户可以取消等待并忽略结果；首版不保证强制中断已经发出的 HTTP 请求或第三方模型调用。

导入和批量操作显示进行中状态及成功、更新、跳过、失败统计。问答与生成在等待时禁用重复提交，但允许切换页面。破坏性操作必须二次确认。

## 错误与配置

后台异常统一映射为中文、可操作的通知，不允许异常穿透 Qt 事件循环。页面具有加载、空、成功和失败状态。模型或嵌入配置缺失时，引导用户修改 `config.toml` 或 `.env`；密钥不得进入控件持久化、日志或 SQLite。

关闭窗口时不再接受新任务，等待正在进行的数据库写事务安全结束；只读结果可以丢弃。数据库、索引与配置错误继续复用现有领域错误和诊断逻辑。

## 测试与验收

- 控制器和视图模型使用假的应用服务覆盖集合切换、成功、失败和过期任务结果。
- 使用 Qt 测试工具覆盖导航、后台状态、删除确认、消息与来源详情。
- 使用临时存储覆盖“创建集合→导入→检索→问答→生成产物”的关键集成路径。
- 保留并运行全部 CLI 和核心回归测试。
- 验收要求 `uv run ragdb-gui` 可启动，完整工作台功能可访问，耗时操作不阻塞主窗口。

首版不包含 EXE 打包、自动更新、多用户/远程访问、可视化主题编辑器或自动化截图基线。

# 旧向量索引维护设计

用户已授权按照[实施计划](../plans/2026-09-25-vector-index-maintenance-implementation.md)进行本阶段建设。

## 数据与归属

SQLite 活动 profile 是保护依据。Chroma 精确名称须同时符合项目格式、所属集合仍在 SQLite 中、`ragdb_collection_id` 元数据等于对应 UUID，才可能成为旧索引候选。当前活动名称总是保护，元数据损坏也不能绕过保护。无法确认归属的对象只报告。命名空间显示为 legacy 或名称中保存的指纹前 24 位，不把该前缀伪装成完整历史模型配置。

预览绑定数据库与向量目录的解析路径、活动指纹、活动命名空间、SQLite 集合列表及 Chroma 集合身份、名称、分类和条数。相同名称被重新创建后，其 Chroma ID 改变，旧预览失效。未创建向量库的空目录返回空清单，不初始化 Chroma；没有活动 profile 时拒绝给出删除目标。

## 执行与故障

清理只接受预览标识，执行前取得与重建共用的跨进程独占门禁并重新盘点；内容变化拒绝执行。逐个目标再次确认身份、归属和活动保护，再按精确 Chroma 集合名删除。清理不会调用模型服务，也不改写配置、密钥、SQLite 切片或 FTS。

Chroma 删除不可与 SQLite 组成事务。部分删除失败时停止后续目标，返回已清理、未清理及安全错误，记录脱敏操作日志并释放门禁；用户重新预览即可重试。门禁沿用现有死进程恢复。清理期间当前索引继续检索，导入、集合/资料删除和模型重建暂时互斥。

## 入口与确认

CLI 增加 `index list-stale` 预览和 `index clean-stale --preview-id ID --confirm` 执行。桌面“任务与诊断”增加“索引维护”页签，盘点与清理均在后台运行；只有有效预览含候选时才可清理。确认列出精确目标和条数，说明清理后若需旧模型必须重新生成向量。窗口关闭时保护正在执行的维护任务。

不承诺删除后立即回收多少磁盘字节，不提供强制删除未知对象、定时自动清理或自动模型下载。验证仅使用临时数据库、合成资料和本地 Chroma。

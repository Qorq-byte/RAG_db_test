# Codex式问答交互设计（待用户确认）

## 目标与方案

原生PySide6问答页参考Codex的对话布局和实时反馈。推荐同时实现消息布局、真实阶段进度及流式正文；仅改布局不能解决长时间无反馈的问题，完整复制Codex工作区则超出本次问答范围。

## 界面

- 用户问题发送后立即显示在右侧圆角消息块；助手回答左对齐，以宽松正文排版显示。保留浅色、深色、跟随系统与减少动效偏好。
- 底部固定多行输入框，Enter发送，Shift+Enter换行，中文输入法选词时不误发送。生成时发送键变为停止键，防止重复请求。
- 助手消息依次展示真实状态：正在检索知识库、已找到依据并连接模型、正在生成、完成。展示已用时间，不显示无法计算的完成百分比，不伪造模型思考过程。
- 正文支持安全Markdown、列表和代码块，提供复制回答。禁用原始HTML与远程资源自动加载；问题按纯文本显示。
- 保留集合选择、新会话、历史会话及引用详情；每条完成的助手消息有对应的引用入口，查看历史也能核对来源。
- 用户在底部时跟随新文本滚动；上滚阅读历史时停止自动滚动，提供回到最新位置入口。长消息及窄窗口保持可读。

## 输出与状态

- Ollama使用流式JSON行，OpenAI兼容云端使用SSE；正确处理拆分数据、结束标记、空增量及错误。仅把服务实际返回的正文增量显示出来。
- 应用服务以事件回调报告检索、生成及正文增量；Qt信号把事件交给主线程更新组件。现有CLI及学习产物保留非流式接口兼容。
- 不支持流式的服务若明确返回不支持错误，可提示用户后按非流式重试；认证、限流、网络错误不静默重复请求。非流式等待也显示真实阶段和耗时。
- 无证据时显示既有“知识库中未找到足够依据”结果，不调用模型。保留现有基于知识库作答约束。
- 同一时刻仅一个问答请求。生成期间禁用集合/会话切换及新会话；后台事件仍校验请求身份，防止迟到结果串入其他对话。
- 停止后立即反馈已请求停止；中断读取或在当前等待超时后结束，网络等待有界。停止、失败时保留当前页面已显示的部分文本，明确标注未完成，允许重新发送。
- 仅完整成功的一轮问题、答案及引用原子入库；失败或停止的部分回答不作为后续模型历史。已开始但没有完整消息的新会话不在历史列表中显示为空白成功记录。
- 关闭窗口时请求停止，等待后台安全退出；不得在仍有后台工作时销毁信号接收对象。

## 验收

1. 原生窗口中核对左右布局、主题、窄窗口、长文本、Markdown、复制及引用交互。
2. 模拟延迟服务验证发送立即可见、阶段更新、首段正文早于最终完成、停止及失败保留文本、重试无重复历史。
3. 流式适配器测试覆盖JSON行/SSE分片、UTF-8、结束标记、无正文、HTTP错误与提前断流；不把不完整输出记录为成功。
4. 集成验证完整回答入库、重启恢复及历史引用；验证页面切换保护、输入法和手动滚动行为。
5. 定向及全量回归通过后提交源码、测试和验收文档，按步骤推送GitHub。

## 发布约束

本轮只改源码与测试；沿用用户要求，所有问题解决并获其明确同意后才构建或发布新安装包。当前v0.1.0不因源码提交而变化。
